# Tailscreen test catalog

Reference for the repo's test suites and seams. Running tests, the E2E surfaces, env-var affordances and the impairment harness live in `.claude/rules/testing.md`, which loads automatically for test files.

## The extract-the-decision pattern

`AdaptiveBitrateTests` is a pure unit test (no tsnet) covering `TailscaleScreenShareServer.nextAdaptiveBitrate` — the loss/recovery decision math and asymmetric hysteresis extracted from the sweep loop. An E2E version isn't viable: the live sweep intentionally no-ops without a capture-helper attached.

The same pattern covers the rest of the server's untestable-live machinery, all CI-able. **When you extract a new pure decision from an async loop for testing, add it to this list.**

### Server / transport decisions

- `ViewerLifecycleDecisionTests` (in the package's `TailscreenSharerTests` target) — audio-relay SSRC anti-spoof gate, idle-sweep staleness math, PLI ring cap, per-viewer RTP header rewrite, the `shouldEnqueue` per-viewer send-chain drop policy shared by the video and audio chains, the `shouldSendFrame` keyframe-only throttle including its sequence-space-contiguity invariant, and the kicked-viewer quiet window `expelledQuietDecision` — a just-expelled addr's straggler KEEPALIVEs are answered with denial instead of re-run through the admission gate, so a one-time kick can't be silently undone in open-door mode.
- `PerViewerFairnessDecisionTests` (in the package's `TailscreenSharerTests` target) — the per-viewer fairness layer: `lossAttribution` distinguishing one-bad-viewer `.isolated` from everyone-suffering `.widespread` (incl. the ≥2-viewers "no-peers" rule and the exactly-at-threshold boundary), and `fairnessDecision` throttling the isolated viewer to keyframe-only, renewing it while it keeps losing, expiring it after a clean window, and excluding throttled viewers from the global `nextAdaptiveBitrate` input so one bad link can't drag the shared rate.
- `HelperRestartDecisionTests` (in the package's `TailscreenSharerTests` target) — helper exit-reason classification, the 3-in-30s crash budget, the hung-helper watchdog predicate.
- `CaptureStopDecisionTests` — `AppState.captureStopAction`, the capture-failure routing (`userInitiated` / `connectionLost` / `helperUnrecoverable` / `sourceClosed` / `attemptRestart`): a non-retryable helper exit tears the share down instead of looping `restartCapture()` against a source that will never come back, split by `classifyHelperExit` into a genuine error (`.slotRefused` / `.permanent` → `helperUnrecoverableErrorDomain` → error alert) vs. the *expected* shared-window/display/app close (the helper's `writeFatal("source-gone: …")` on a `PickerReconstructionError` → `.sourceGone` → `helperSourceGoneErrorDomain` → `.sourceClosed` → a gentle `presentNotice`, not an error). Only the terminal domains (those two plus `receiveLoopErrorDomain`) stop outright; everything else still gets one fresh-budget restart. The mid-share source close is caught either by the SCStream delegate `didStopWithError` or an in-band `SCFrameStatus.stopped` frame (`ScreenCapture`'s stop bridge, gated by `beginStopping()` so a deliberate `stop()`/changeSource helper swap isn't mistaken for a window vanish), both flowing to the same respawn → `windowNotFound` → `source-gone` teardown.
- `ReceiveLoopPolicyTests` — the shared UDP receive-loop retry policy (`ReceiveLoopPolicy`: 250 ms → 5 s capped backoff, consecutive + windowed give-up thresholds, and the elapsed-time `readFailed` dead-socket classification) both loops consult instead of dying on the first receive error.

### Video / codec decisions

- `ParameterSetExtractionTests` — `ParameterSetExtraction`, the one NAL-type-mask table every in-band SPS/PPS/VPS pull goes through (the Linux/Windows libavcodec sharer backends and, via `VTVideoDecoderAdapter.parameterSets(fromAVCC:)`, the mac viewer): the H.264 `& 0x1F` vs HEVC `(>> 1) & 0x3F` type masks, all-or-nothing on a partial set, first-wins on duplicates, and the crossed-mask cases that would otherwise fail silently — a perfect-looking sharer whose viewers install no parameter sets and see black. The mac adapter's AVCC wrapper is pinned by `ViewerSessionAdapterTests`.
- `DecodeRecoveryDecisionTests` (in the package's `TailscreenViewerTests` target) — the viewer's consecutive-decode-failure escalation ladder (`DecodeRecovery.action` in `TailscreenViewer`: PLI → decoder recreate → degraded badge → alert; `>=` thresholds + a per-episode fired-rung latch so each rung fires once even if the counter skips a value). Moved from the mac target when the ladder went portable: the macOS `VideoDecoder` still applies it internally (counter on its serial queue, VT-session rebuild on `.recreateSession` — the live wiring is pinned by `VideoCodecTests`' garbage-feed test), while `ViewerSession` applies the same rungs for hosts whose decoder reports per-frame failures through the `VideoDecoding.onDecodeFailure` seam. The session-side wiring is pinned in `ViewerSessionTests`' ladder section: with neither `onDecoderResetNeeded` nor `onDecodeFatal` installed the flat one-PLI-per-failure path is byte-identical to before (the macOS client stays on that non-path — its VT adapter never invokes the session's `onDecodeFailure`, so mac cannot double-ladder); with them installed, the reset rung fires the host callback once (plus the keyframe request the rebuilt decoder needs), the terminal rung surfaces once, and a successful decode resets counter + latches so a new episode walks the rungs again. The GTK and WinUI hosts opt in via `TsnetTransport.run`'s `onDecoderResetNeeded`/`onDecodeFatal` parameters (`FFmpegVideoDecoder.reset()` + each host's failure surface).
- `ColorInfoTests` — the wide-gamut / 10-bit / HDR color model (`ColorInfo`: display-capability → color-space selection wide-gamut→P3 / HDR+10-bit→BT.2020 PQ / else BT.709, the VideoToolbox CFString-key + `CGColorSpace`-name mappings, `profileLevel` HEVC Main-vs-Main10 selection, `capturePixelFormat` 8-vs-10-bit, `captureColorSpaceName` overriding only non-709, renderer-side `layerColorSpaceName(forPrimaries:)`, `downgradedTo8Bit`, Codable round-trip) plus `VideoEncoder.sessionAttempts` — the Main10 → HEVC-8-bit → H.264 fallback-ladder ordering. The color/bit-depth ride the SPS VUI in-band (no wire change), the only new byte being the optional PROFILE_NO (0x09) 8-bit-fallback control message (round-trip pinned by `RTPPacketTests`), and the live capture→encode→decode→render path is local-only (`ScreenShareCaptureHelperTests` can assert the encoded SPS primaries/depth; EDR rendering is visual-check-only).
- `CaptureTimingsTests` — the sharer-side "which stage is slow" split (`CaptureTimings`/`CaptureTimingAccumulator`: per-window averages with acquire averaged over every pass but convert/encode over encoded frames only — a still screen must not read as a fast sharer — the window reset, the zero-frame no-divide, and `slowestStage` naming the one to fix).
- `FFmpegCaptureEncoderBaseTests` (in `Packages/TailscreenVideoFFmpeg`, run by the `linux-viewer` job) — the pure decisions of `FFmpegCaptureEncoderBase`, the scaffolding the X11/WGC/portal capture backends subclass: the encoder-attempt ladder (in-order, first-open wins, unavailable names skipped without an attempt entry, the exact `encoderUnavailable` detail texts) via an injected `open` closure, the 30-strike `SourceGoneBudget` with its `source-gone:` message the server's `classifyHelperExit` routes on, `anchoredBitrate` (the `EncoderTuning` formula + ceiling clamp, per-codec bits-per-pixel), the `EncodeSettings` quality-env decode (defaults, the `forceH264` latch beating the HEVC preference, garbage tolerated), and the frame-pacing remainder math incl. the `max(1, fps)` divide-by-zero clamp. Lives in that package, not TailscreenKit, because the base names `FFmpeg.VideoEncoder`.

### Audio decisions

- `VoiceResilienceDecisionTests` (in the package's `TailscreenProtocolTests` target) — the voice-path resilience decisions extracted from `VoiceChannel` into the portable `VoiceReceiveDecisions` namespace in TailscreenAudio (PT→route demux, decoder-failure cooldown gate, wrap-aware sequence-gap concealment, adaptive jitter-buffer sizing, clamp-log throttle, single-pass clamp, idle-SSRC eviction, concealment cap + fade-out, starve-resume verdict, pause detector), with the `LossyChannel`-driven end-to-end case (seeded loss/reorder/dup → `receive` → concealment counters) living mac-side in `VoiceChannelTests`. How the decisions COMPOSE on the portable side — `VoiceDownlink`'s Opus-PLC concealment, cooldown, eviction and jitter-target legs — is pinned by `VoicePathTests`' loss-resilience section (explicit `nowNs` clock, deterministic), and the `OpusVoiceDecoder.conceal()` PLC entry point by `OpusAudioCodecTests`.
- The 960-sample framing (exact boundary, remainder carry, multi-frame drain, order preservation) is the portable `PCMFramer` (TailscreenAudio), pinned by the framing section of the package's `MicrophoneCaptureTests` — the mac tap paths (`SystemAudioTap`, `TapBuffer`) consume it rather than keeping their own framers.
- `SystemAudioRoutingTests` — the viewer-side demux in process: a real PT-99 packet through `VoiceChannel.receive` fires `onSystemAudioPCM` and never `onMixedPCM` (the pure `audioRoute` PT→route decision it exercises is pinned package-side in `VoiceResilienceDecisionTests`). `RTPAudioTests` and `CaptureHelperWireTests` also carry system-audio cases (PT-99/SSRC-1 packetizer, depacketizer accepting 98/99 while still rejecting 96/97, the `audioAccessUnit`/`setAudioEnabled` frame round-trips, and the `PickerSelection.captureAudio` field's backward-compatible decode).

### Access control, consent, and requests

- `ViewerAccessPolicyTests` — the viewer-consent logic: the `admissionDecision` gate precedence (blocklist > allowlist > approval gate, incl. the unresolved-identity park when the deny list is non-empty), the `drainDecision` blocklist-aware toggle-off drain, the `connectedDenyList` policy→deny sweep of the connected roster (a "Deny & Block" on an already-connected peer expels it, not just future HELLOs), the `canAcceptPending` pending-cap DoS bound, the shared `readFailed` dead-socket-vs-timeout classification the request-response wait reuses, and the `ViewerAccessPolicyStore` persistence round-trip (injected `UserDefaults` suite). The tri-state approval-default migration (unset → on, stored choice sticks, `TAILSCREEN_OPEN_DOOR=1` override) lives in the portable `ViewerApprovalPreference`, pinned by the package's `ViewerApprovalPreferenceTests`.
- `ShareResponseProtocolTests` — pins the `.shareResponse` (0x05) wire format: accept/decline round-trip, unknown-type-byte skip (old-peer compat), garbage/wrong-kind payload rejection.
- `ShareRequestInboxTests` — the sharer's incoming-ask inbox (`ShareRequestInbox`, the coalescing, cap and expiry lifted out of the AppKit-bound `TailscreenMetadataService` so Linux and Windows get them too): retries coalescing on the requester's **source IP** rather than the hostname it supplies, which is the whole point — a peer picks its own hostname, so keying on it lets one machine stack `maxPending` rows and pin one held-open connection each, and the test constructs exactly that flood; plus the retry keeping the row's identity while taking the fresh connection ID, a full inbox still accepting retries from peers already in it, the split-on-last-colon `sourceKey` that keeps two IPv6 peers apart, and an expiry that ignores a clock that went backwards instead of wrapping into an enormous age and dropping everything.
- `SharerAccessCoordinatorTests` — the StableNodeID-resolution queue behind "Deny & Block", with no tsnet node.
- `ViewerRosterDecisionTests` — the roster-row actions and the shared intent queue itself (`ViewerRosterDecision.PendingIntents`: apply-on-resolve, last-write-wins, prune-on-departure, and `expelledByPolicy`). All three hosts hold this queue now — macOS's `AppState` swapped its own `resolvableIntents` dictionary for it — so the rule is pinned once here rather than per host.
- `SharerAskToShareCoordinatorTests` (in the package's `TailscreenSharerTests` target, and the one suite there that uses `@testable` — the reply-send seam is internal) — the ask-to-share sequencing all three hosts share (`SharerAskToShareCoordinator`): an answer riding the ARRIVAL connection, and the freshest one after a retry coalesced (an answer down the stale connection reaches nobody); accept firing `onPreApproveViewer` strictly BEFORE `onStartShare` so the invitee's imminent HELLO cannot park at the gate of the share they were just invited to; a no-connection accept still pre-approving and starting; the expiry-on-arrival prune; a capped-out flood arrival publishing nothing; and clear-once idempotence. `LinuxShareSessionTests` (in `TailscreenLinuxBackends`) smoke-tests the GTK engine's wiring onto it plus the engine's held-IP replay contract.

### UI-model decisions

- `AnnotationCanvasModelTests` — the shared canvas state machine (undo stack, remote upsert/idempotence, ephemeral clicks).
- `AnnotationStoreTests` — the portable VIEWER canvas (`AnnotationStore`), which had no suite of its own until it grew two silent accumulation bugs: an `.add` for a known id appending instead of upserting (a drag re-sends one id every few milliseconds, so the store grew without bound and the renderer overdrew every copy), and ephemeral `.click` markers never being swept (the sharer's half dropped them at 0.8 s, the viewer's kept them for the share). Driven on an explicit `nowNs`, the `VoicePathTests` discipline, so the boundary cases are exact rather than slept for. The lifetime itself is `ReceivedAnnotations.ephemeralLifetimeNs`, read rather than copied — two tables would let one screen's marker outlive the other's.
- `AnnotationRenderingTests` — displaying viewers' strokes on a sharer with no drawing framework (`ReceivedAnnotations`: the drag upsert that must not stack one stroke into hundreds, unknown-undo as a non-change, click-marker expiry leaving other tools alone, an undone ephemeral not leaving its deadline behind; `AnnotationRasterizer`: premultiplied alpha — getting it wrong is a dark halo rather than an error — coverage-based antialiasing, off-screen clipping, and draw order).
- `ViewerZoomMathTests` — the viewer's continuous content zoom/pan geometry (`ViewerZoomMath`: cursor-anchored zoom, scale and pan-offset clamping, smart-magnify toggle — extracted from `AspectFitHostView`'s gesture handling).
- `OverlayModeDecisionTests` — `AppState.overlayMode(for:)`, the pure `PickerSelection` → sharer-overlay-mode projection (incl. missing-ID fallbacks) used at share start and by the mid-share "Change Source…" flow, which must rebuild the overlay because its mode is immutable.
- `CaptureBackendSelectionTests` — which capture backend a Linux share uses: X11 root capture, the ScreenCast portal, or a refusal. The branch worth the suite is that **a Wayland session never gets X11 capture even though `$DISPLAY` is set** — XWayland sets it, so the obvious gate passes and the share succeeds while sending viewers an XWayland root that is usually blank, with the UI saying "Sharing" and nothing erroring. Also pins that a window/app share is the portal or nothing (widening it to the whole screen would be a privacy failure, not a missing feature), that an X11 screen share KEEPS X11 rather than gaining a consent dialog it did not ask for, that `unknown` sessions with a display are X11 (`startx`, containers, forwarded SSH), and that session detection never consults `DISPLAY`. The app-side wiring — reading the environment — is gated separately by `tailscreen --capture-backend-report` on the `linux-app` leg, because a decision fed the wrong inputs is exactly as wrong as a wrong decision.
- `PortalCapturePlanTests` — every decision the ScreenCast-portal capture backend makes, extracted because that backend can never be gated end to end (a share begins with a consent dialog a person clicks, so there is no headless path to a frame and there never will be). Covers the routing that matters most — a producer going away is the user pressing "stop sharing" in their compositor, so it must reach `onUserStopped`, since `onUnexpectedExit` would make the server respawn and put a fresh consent dialog in front of somebody who just said stop — plus the even-rounding a 4:2:0 encoder needs, the resize→rebuild path (the portal is the only backend that can share a single window, and windows get resized), and the rebuild debounce, which is timed from the last REBUILD rather than the last mismatch so a continuously dragged window still recovers instead of staying frozen.
- `FrameHandoffTests` (in `Packages/TailscreenSharerPortal`) — the PipeWire-thread → encode-thread double buffer, and the one invariant that matters: the encoder never reads a buffer the converter is writing. Driven DETERMINISTICALLY — the conversion is stopped mid-write and `publish` is called from another thread at that exact moment — because the window is narrow enough that a stress loop misses it: an earlier probabilistic version of this test scored zero hits in 3000 iterations against a `publish` with the `writing` check deleted. The stress version is kept alongside, labelled as the smoke test it is.
- `SharerDrawingLatchTests` — the arm/disarm decisions BOTH swift-cross-ui sharers make when the person sharing picks up a pen (`SharerDrawingLatch` / `SharerDrawingSurfacePlan`): tapping the armed tool again disarms, switching tools keeps the surface that already fought for focus rather than rebuilding it, a host's refusal disarms anyway and carries its reason for the sharer to read, teardown disarms even with nothing armed, and no capture region refuses instead of guessing one. Portable because the two hosts' surfaces are nothing alike — an X11 override-redirect overlay and a Win32 uniform-alpha scrim — while the decisions about when to raise and drop them are identical, and both failure modes are a person locked behind a fullscreen window.
- `ScreenRegionInverseTests` — `ScreenRegion.normalizedPoint`, the tested inverse of `point`: round-trips, the last pixel landing at exactly 1.0, an off-edge drag clamping to the NEAR edge rather than wrapping to the far one (a Win32 `LOWORD` read of a signed coordinate pair does exactly that, teleporting the stroke across the screen), and a degenerate region not dividing by zero.
- `QualitySettingsTests` — the quality-settings model (`QualitySettings`: preset→knob mapping, fps/ceiling normalization clamps, helper-env round-trip, `UserDefaults` persistence with decode-with-fallback) and pins the centralized `TransportTuning` / `EncoderTuning` constants to the literals they replaced — including the `clientIdleDisconnectNs == viewerIdleTimeoutNs` invariant.
- `PeerShareStatusMapTests` (beside `PeerListFilterTests`) — `PeerShareStatusMap`, the upkeep of the per-peer sharing-status cache the filter's tri-state reads. Two lines of code that every hub had written slightly differently: the GTK picker's manual refresh cleared a peer's status on a no-answer while its 10 s quiet refresh kept the previous one, so the same chip meant different things depending on which pass ran last. A no-answer is status-UNKNOWN and therefore CLEARS — keeping the last answer is stale-positive by construction, and the failure a person acts on is a chip inviting them to connect to a share that ended.
- `PeerListFilterTests` — the peer-list filter: the macOS hub's and, since the same pure types now back `TailscreenHubUI`'s header menu, the GTK and Windows hubs' too (both apps keep their discovery result raw and render a `filteredPeers`-style projection, exactly as `AppState` does; on those hosts the tag axis rides `DiscoveredSharer.tags` and the sharing axis a lazy `TsnetTransport.fetchMetadata` sweep off each discovery). Covers `PeerListFilter.matches` — the pure hide-offline ∧ only-sharing ∧ any-of-selected-tags decision with the explicit untagged bucket, which is only consulted while a tag filter is active, and the tri-state sharing input (`PeerSharingState` — deliberately an enum, not `Bool?`) where `.unknown` deliberately hides while the "Only screens being shared" axis is on — the `tag:`-prefix `displayName` stripping, and the `PeerListFilterStore` persistence round-trip via an injected suite incl. the older-blob decode-with-fallback that loads new axes off instead of resetting the filter. The tags themselves ride the netmap both discovery sources already deliver (`IpnState.PeerStatus.Tags` / `Tailcfg.Node.Tags` → `TailscreenPeer.tags`), so there's no probe and no wire change, and `AppState.availablePeers` stays the raw unfiltered list (`filteredPeers` is the projected view) so `TAILSCREEN_AUTOCONNECT_TO` and the filter menu's tag enumeration see every peer. The sharing axis's fetched input is cached in `AppState.peerShareInfo` (populated by the lazy `refreshPeerShareStatus()` sweep over `TailscreenMetadataClient.fetchMetadata`; no-answer removes the entry so it can never go stale-positive), and `ScreenShareProtocolTests` pins the `.metadataRequest`/`.metadataResponse` (0x0B/0x0C) wire pair — round-trips incl. the idle not-sharing answer, the 128-char display-string clamp, garbage-payload-decodes-to-nil without poisoning the stream.
- `AppCloakTests` — the Cloaked Apps layer: the pure `AppCloak.effectiveExclusions` decision (`.display`-only, main-toggle-gated, order-stable dedupe — window/app shares never cloak, an explicitly picked app wins), the `AppCloakStore` persistence round-trip (injected suite, tri-state enabled default on, re-add refreshes the display name without duplicating, corrupt blob degrades to empty), and the `PickerSelection.excludedBundleIDs` JSON contract (round-trip, missing-key-decodes-`[]` back-compat, the `settingCaptureAudio`/`settingExcludedBundleIDs` copy helpers preserving each other). The live `SCContentFilter(display:excludingApplications:…)` effect is local-only, and the mid-share re-push rides the `changeSource` path `ScreenShareCaptureHelperTests` already exercises.
- `ProfileStoreTests` — the multi-account profile registry (`ProfileStore`/`TailscreenProfile`: first-launch migration onto the legacy `tailscale` state dir, unique `profiles/<uuid>` dirs for added accounts, active-selection persistence via an injected suite, remove-refuses-active/last, corrupt-blob degradation to the default profile, the `tailnetName`/`profilePicURL` missing-key decode defaults that keep pre-field registries loading, `menuTitle`'s tailnet-qualified label — the disambiguator when one login spans several tailnets — and the instance-suffix-at-resolve-time `statePath` contract — a profile is just a tsnet state directory; `AppState.switchProfile` closes the node locally without logging out, so inactive profiles stay signed in on disk) plus the pure `AppState.canSwitchProfile` gate (switching closes the node, so *every* non-idle state — a share still starting, a viewer still connecting — blocks it).
- `PeerConnectionInfoTests` — now in the portable package, with `PeerRoute` / `ConnectionQualityTier` themselves (all three hubs render this line, and `TailscreenHubUI` cannot import a macOS app target). Pins the peer-detail pane's connection decisions (`PeerRoute.from`: a populated `curAddr` outranks a relay because tsnet reports both mid-upgrade, and LocalAPI's empty-string-not-absent convention must not render "DERP ()"; `ConnectionQualityTier.forLatency`: exclusive 60/150 ms bounds, cross-checked against the named constants so a retune can't silently invert the tiers).
- `LocalizationCatalogTests` — enforces the localization rule "keys byte-for-byte in sync" by scanning `L("…")` call sites against `en.lproj/Localizable.strings`. It lives in **`Packages/TailscreenL10n/Tests`**, not with the mac suites, and scans ALL FOUR source trees — the three apps plus `TailscreenHubUI` — because the catalog is shared. That placement is the whole point: a Linux job is the only CI machine that sees the GTK and WinUI apps' sources on every PR, so a mac-side version of this test would watch one app's keys and let the other two rot. It also pins that a translation carries no key the base catalog has dropped and takes the same number of values as its key. Its neighbours (`StringsFileTests`, `LocalizationFormatTests`, `LocalizationKeyTests`, `LocalizationLookupTests`) cover what replaced `String(localized:bundle:)`: the `.strings` parser, `%@`/`%lld` substitution, and language resolution.
- `TimeoutTests`, `ShareLockTests`, `RTPBufferPoolTests`, `AppErrorTests`, and `MenubarIconStateTests` (menubar glyph precedence incl. the pending-request badge and the control-request + waiting-viewer badges on the sharing glyph, control outranking the waiting viewer) pin down the small utilities.

### Remote control

- `WindowsCaptureRegionTests` — the Windows sharer's where-is-the-target problem (`WindowsCaptureRegion.resolve`: a WGC `GraphicsCaptureItem` carries no HMONITOR, so its SIZE is matched against the enumerated monitors — unique match resolves, a window-sized item is `.notADisplay`, and **two identical monitors decline** rather than guessing, since a click landing on a screen the viewer can't see is worse than no click; the failures carry sharer-facing reasons so a missing Request Control isn't a mystery).
- `WindowsPointerMappingTests` — the Windows half of the same problem (`WindowsPointerMapping`: normalized → screen → `SendInput`'s 0…65535 virtual-desktop absolutes — the `65535/(extent-1)` scale factor that makes the last pixel column reachable, negative `SM_XVIRTUALSCREEN` origins from a monitor left of the primary, clamping instead of wrapping outside the desktop, and `WHEEL_DELTA` saturation in a signed 16-bit field).
- `SendInputInjectorTests` — the injector's decisions (revoke TOCTOU: an event queued before `deactivate()` never lands after it; the synthesized button-up so a revoke mid-drag can't strand a held button; modifiers pressed around each key and released in reverse, since Windows has no per-event modifier field the way `CGEvent` does; Caps Lock never synthesized because it is a toggle; unmappable HID usages dropped rather than guessed; the extended-key bit that distinguishes Right Arrow from numpad 6) — all through the `onInjectForTesting` seam and an injectable `virtualDesktopProvider`, so they run on Linux CI with no real `SendInput` and no cursor moved.
- `RemoteControlMappingTests` — the opt-in remote-control coordinate mapping (`RemoteControlMapping.globalPoint`: normalized `[0,1]` → global-Quartz per share kind, non-zero + negative (multi-display) origins, out-of-range clamping; `boundingRect` app-window union; and `captureRect`'s per-kind branch selection via injected resolvers — crucially that an **application** share clamps to the union of the app's window rects, NOT the whole display, so a granted viewer can't click the menu bar/Dock/other apps).
- `RemoteControlPolicyTests` — the grant/flood decisions (`RemoteControlPolicy.shouldInject` connectionID gate incl. nil-grant deny, `coalesceMouseMoves` consecutive-move collapse that never drops button/scroll/key events, `EventRateLimiter` sliding-window ceiling + no-record-over-budget recovery), plus the notice **projections** (`AppState.noticeCandidates` — that control requests key by viewer IP, not by the reconnect-minted connectionID, and that the roster/gate key by `ip:port` instead; the dedupe *rule* they feed lives in the portable `SharerNoticeTests`) and the `RemoteControlDefaults` round-trip.
- `RemoteControlInjectorTests` — the injector's revoke gate (input dropped once `deactivate()` seals it — the post-revoke TOCTOU fix), the stuck-button release (a button held at revoke gets a synthesized button-up, incl. middle), and the neutral-wire → CGEvent translation (`eventFlags` per-bit + unknown-wire-bits-ignored, HID→kVK key translation, unmappable-HID-usage dropped, modified clicks/scrolls carrying their translated flags to injection), all via the `onInjectForTesting` seam so no real `CGEventPost` warps the CI cursor.
- `MacKeyCodeMappingTests` — pins the kVK↔HID table (bijectivity: mac→mac must reproduce the exact keycode — spot rows, fn/Insert unmappable) and the viewer-side `keyModifiers(from:)` capture mapping.
- `GlobalHotkeyTests` — pins `handlerShouldFire` (the Carbon id-dispatch filter that stops one hotkey's handler swallowing another's — the regression where registering the revoke hotkey killed the mic toggle).

The `.controlRequest`/`.controlGranted`/`.controlRevoked`/`.inputEvent`/`.controlReleased` wire round-trips, the revoke-reason clamp, the malformed-`.inputEvent`-decodes-to-nil case, and the oversized-frame-length DoS guard (`ScreenShareMessage.maxPayloadLength` → `ScreenShareMessageParser.isCorrupt`, inclusive boundary) are pinned in `ScreenShareProtocolTests`; the live grant flow rides local-only tsnet in `ScreenShareRemoteControlTests` above. Real `CGEvent` injection needs Accessibility TCC and is manual/local-only. `ScreenShareProtocolTests` additionally pins the NaN/Infinity/`1e999`-rejecting `.throw` decoder default on `.inputEvent` payloads, with the NaN-safe `RemoteControlMapping.globalPoint` clamp (non-finite → 0) in `RemoteControlMappingTests` as defense-in-depth.

### Sharer surfaces (notifications, hotkeys)

- `SharerNoticeTests` — `SharerNoticeDecision`: *when* to interrupt the sharer and about whom (forget-on-leave over whole-list snapshots, the opaque `identity` so callers can key by IP or `ip:port`, `blocksSomeone` implying actionable, and `dismiss` never being an offered button). `SharerNoticeReconcilerTests` sits beside it for the reconcile LOOP both swift-cross-ui hosts now delegate to (`SharerNoticeReconciler` over the `NoticePosting` seam): announce-once/withdraw-gone through a fake poster, the departure banner replacing the arrival and carrying the label remembered from it (the peer is gone from every live list by then), per-kind books that don't collide on one identity, the answered-from-the-banner `forget` re-arming a fresh ask, and `reset()` keeping teardown silent. macOS keeps its own `noticeCandidates`-based wiring (different shape; a follow-up). Plus `SharerNotice.decodeID`, the tested inverse of `id` — needed by a host whose platform hands a press back as ONE opaque string, which is Windows. It splits on the FIRST colon because kinds never contain one and identities routinely do (`100.64.0.1:51820`), and splitting anywhere else reroutes an answer between "let this person watch" and "let this person control my machine".
- `SharerNoticeTextTests` — the words, the two freedesktop capability degradations (no `actions` drops the buttons *and* changes the text to say where to answer; no `body` folds the peer's name into the summary, name first, because a summary truncates from the end), and `action(forKey:)`: the two answer keys map to answers and **everything else maps to `dismiss`**. That last one is the load-bearing half — clicking a Windows toast's BODY activates the app carrying `openActionKey`, and reading it as a deny would decide about a peer because somebody looked at the notification.
- `ShortcutCatalogTests` — every keyboard shortcut as data, with `collisions(_:)` checked per display style because `primary` and `control` are distinct on macOS and both collapse to Ctrl elsewhere.
- `WindowsToastPayloadTests` — `WindowsToastPayload`, the Windows delivery decisions, which are unusually worth extracting because **all three of their failure modes are silent and identical**: an unescaped `&`/`"` in a peer's hostname makes the toast XML unparseable (that peer's notice alone goes missing), an `AppNotification.Tag` over 64 characters is refused rather than truncated (post *and* withdraw both miss), and `scenario="urgent"` is a Windows 11 attribute whose unrecognized value is a schema violation on Windows 10 rather than an ignored hint. Also the activation-argument round trip — the one seam a button press crosses, since the press comes back through AppLifecycle rather than the shim — and the FNV-1a tag, pinned as a literal digest because `Hasher` is salted per launch and would satisfy any same-process comparison while never withdrawing what the last run left on screen.
- `WindowsNotifierTests` (in `Packages/WinNotifyKit`) — the layer between the host and the shim, through a `deliverForTesting` seam: which scenario, which tag, which priority, and that an unregistered notifier degrades quietly rather than crashing. **Read its header before trusting it**: there is no `AppNotificationManager` off Windows and nothing stands in for one, so nothing here posts a toast, sees a toast, or presses a button — the same honest limit `WASAPIKit` states for its own Linux leg. A wrong tag and a right tag both post, which is why a Windows runner would not have caught these either.

### Loss recovery (NACK + receiver feedback)

Four CI-able pure suites:

- `LossRecoveryWireTests` (in `RTPPacketTests.swift`) — NACK/RR/PING round trips, the `ScreenShareCaps` extended-HELLO/HELLO_ACK handshake, and the legacy-5-byte-`decodeHelloAck`-rejects-6-byte back-compat contract.
- `NACKSchedulerTests` — the viewer's `NACKScheduler`: reorder tolerance so pure reordering never NACKs, the RTT-keyed re-NACK cadence, PLI fallback on ring-age / attempt exhaustion, and `packFCI`. Also pins the FCI datagram cap (`fciCappedSeqs`), the >maxGaps discontinuity → PLI fallback, the NACK→retransmit RTT self-measurement, the 65535→0 wraparound block (gap across the wrap NACKed, straggler fills + feeds RTT, >maxGaps discontinuity across the wrap → PLI, and packFCI's current not-wrap-aware two-group split — an efficiency wart pinned so a future fix can't silently drop coverage), `cancelGap` (clears without an RTT sample or PLI), `noteRecovered` (advancing past a recovered tail-of-batch/marker seq so the next batch opens no phantom gap, while genuinely skipped seqs still open gaps), `setReorderTolerances` (in-place FEC arm/disarm preserving gaps + RTT estimate), and the FEC-mode N+2/25 ms tolerances.
- `RetransmitBufferTests` — the send-side `RetransmitBuffer`: wrap-safe seq→template lookup, the triple age/bytes/count eviction, the pure token-bucket `retransmitDecision` budget, and `RetransmitBuffer.has()` agreeing with `template()` after batch eviction.
- `CongestionDecisionTests` (in the package's `TailscreenSharerTests` target) — `nextCongestionDecision`: the RR-loss-fraction cut/hold/raise bands, NACK-vs-PLI weighting, the 60→30→15 fps-ladder transitions with hysteresis, legacy-PLI-input parity so `AdaptiveBitrateTests` stay valid unchanged, the fps-recovery clamp to the session cap, `congestionInputs` isolating an RR-lossy-but-PLI-quiet viewer instead of letting it set the global rate, and recovery not being blocked by served NACKs.

`RRAccountingTests` covers `RRAccounting` — the viewer's receiver-report bookkeeping extracted from the client, fixing the baseline off-by-one and duplicate-inflation defects (first arrivals only, via a 4096-bit sliding dedupe window sized to the retransmit horizon; a served NACK retransmit still counts as received).

### FEC layer (XOR single-parity, phase 2 of loss recovery)

- `FECCodecTests` — parity/recover round trips for every group position incl. the marker packet, mixed lengths, HEVC, seq wrap-around, `groupRanges` **balanced** packing (⌈count/N⌉ equal-sized groups so the marker packet is always covered — no sub-`minGroupSize` remainder), plus the ≤16 clamp, malformed-body/member rejection — recovery never emits a torn packet.
- `FECGroupBufferTests` — single loss solved on parity arrival, parity-before-member reordering, ≥2-loss parity aging out to NACK, fully-received parity dropped, the at-most-once late-original guard, and the bounded media ring never mis-solving after eviction.
- `FECOverheadDecisionTests` (in the package's `TailscreenSharerTests` target) — `fecSweepDecision`: the strictly PER-VIEWER RTT ∧ loss gate with exclusive boundaries (cross-viewer worst-RTT/worst-loss mixing must never turn FEC on with nobody gated, and encoder compensation follows the gated set, never a held N), the 10/7/5 raw-loss ladder over the gated viewers, raw-loss reconstruction from residual + `fecRecovered` + `nackRecovered` against each viewer's OWN expected packet count (multi-viewer recoveries don't inflate; a throttled viewer's small denominator keeps its gate stable; a NACK-masked-but-high-raw-loss viewer at high RTT still gates on), the anti-oscillation case where FEC hiding all loss stays on, the two-clean-window off-hysteresis, legacy-viewer invisibility, and the N/(N+1) `fecCompensatedBitrate` with its scaled-floor clamp.

`RTPPacketTests` pins the 0x0D codec (round trip incl. max-size body, truncated/garbage/oversized → nil, count bounds) plus the 20/22/24-byte RR both-lengths compat (the 24-byte form carries `fecRecovered` + `nackRecovered`) and the `NACKScheduler` served-retransmit recovery counter (`drainNackRecovered`, distinguishing a NACKed-then-filled gap from pure reordering). The closed loop additionally pins per-group parity INTERLEAVING (early-group loss in a multi-group keyframe recovered with zero NACKs) and the covered-marker-loss case (recovered final packet leaves no phantom gap).

### Wire registry and fuzzing

- `WireByteRegistryTests` is the single source of truth for **every wire constant**, pinned per channel (TCP message types + framing constants, UDP control bytes + `ScreenShareCaps` bits, helper-wire `OutType`/`InType`, the picker framing by writer→reader round-trip, RTP payload types + reserved SSRC ordering, the `KeyModifiers` wire bits) with exactness/exhaustiveness (`CaseIterable`)/per-channel-uniqueness legs and failure messages that name both claimants. **Add a registry row whenever you add a wire byte, and never renumber a shipped one.**
- `ParserFuzzTests` is the deterministic seeded byte-level fuzz harness (random bytes / truncations / bit-flips / length-field mutations × the framed TCP parser, RTP depacketizers + `RTPHeader.decode`, UDP control decoders, `AudioRTPDepacketizer`, and `HelperScreenCapture.decodeParameterSets` incl. re-based `Data` slices); seeds derive from loop indices and are printed on failure.
- `SoakTests` (env-gated on `TAILSCREEN_SOAK=1`, nightly workflow) reruns the same `ParserFuzzHarness` at ~50× plus a seeded `LossyChannel` impairment matrix.

## Where a suite lives

Suites whose subject types live entirely in `TailscreenProtocol`/`TailscreenAudio` belong to the package's `TailscreenProtocolTests` target so Linux CI (`linux-protocol`) runs them. The sharer-tier decision suites — `CongestionDecisionTests`, `FECOverheadDecisionTests`, `PerViewerFairnessDecisionTests`, `HelperRestartDecisionTests`, `ViewerLifecycleDecisionTests`, whose subject is `TailscaleScreenShareServer`'s public `static func` decisions — live in the package's `TailscreenSharerTests` target (plain `import TailscreenSharer`, no `@testable`: the decision surface is deliberately public, see the package README's carve-out — `SharerAskToShareCoordinatorTests` is the one exception, `@testable` for its internal reply-send seam), so the same job runs them too. Suites that touch mac-only symbols stay in `Apps/macOS/Tests/TailscreenTests`: anything importing an Apple framework, the `AppState`/`VideoDecoder` decision suites, and the impairment/fuzz cluster (`RTPLossyChannelTests`, `ParserFuzzTests`, `SoakTests`) whose shared `LossyChannel`/`ParserFuzzHarness` helpers still have mac consumers. (The former `VoiceChannel` decision suite moved with its subject: `VoiceResilienceDecisionTests` now pins the portable `VoiceReceiveDecisions` from the package target.) Suites about **strings** are a third home: they belong to `Packages/TailscreenL10n/Tests`, since the catalog serves every app and the checks have to run where all four source trees are visible. See `.claude/rules/portable-packages.md` for the full migrated list.
