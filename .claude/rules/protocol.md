# Network protocol — port 7447 (TCP **and** UDP)

**`docs/spec.md`** is the normative spec (RFC 2119, requirement IDs, wire-value registry appendix). This file is working notes on why mechanisms are shaped as they are and what broke.

**A wire change lands in one commit across four places:** the code, `WireByteRegistryTests` (one table per channel: TCP types, UDP control bytes + caps bits, capture-helper `OutType`/`InType`, picker framing, RTP payload types + reserved SSRCs — exact values, exhaustiveness, per-channel uniqueness), the spec's registry appendix, and a conformance vector. Never renumber a shipped byte. Uniqueness is per-channel by design (TCP types and UDP control bytes overlap on purpose, as do `OutType`/`InType`).

Three independent harnesses pin this, each catching what the others can't:
- `make test-conformance` runs `conformance/vectors/` against `sdk/go` (public Go SDK, written from the spec alone) — proves the spec is implementable from the doc alone.
- `ConformanceVectorTests` (in `make test-protocol`) runs the same vectors against the shipping Swift codecs — proves the spec matches what ships.
- `make test-differential` (`Packages/TailscreenDifferential`, `linux-differential`) links the Go SDK's c-archive via `CTailscreen` and drives both implementations with identical seeded, clock-injected input, asserting identical output at every step of the STATEFUL pipeline (reorder buffer, depacketizers, NACK scheduler, FEC group buffer, RR accounting) — vectors can't express clock-driven interleavings. Separate package because two Go c-archives can't share one binary. A behavioral fix to one side of a ported pair (including deliberate warts, e.g. `PackFCI`'s non-wrap-aware sort) must land on both sides in the same commit — fixing one alone is a differential failure.

## Wire mechanisms (see `docs/spec.md` for exact byte layouts)

- **Video — UDP RTP.** AVCC NALs; parameter sets in-band on every keyframe; PLI keyframe ~2s. PT 96 = H.264, PT 97 = HEVC, viewer auto-detects from RTP PT, no out-of-band negotiation.
- **Loss recovery — capability-negotiated in extended HELLO/HELLO_ACK** (`0x00`/`0x04`, caps bits: NACK, receiver-report, FEC, plus sharer-only `.remoteControl`/`.annotations`/`.openLink` UI-gating bits; bit 7 is reserved as the extension flag, so the byte is full). Legacy 5-byte `decodeHelloAck` rejects the 6-byte form → stays PLI-only. **Viewer re-sends HELLO until acked** (~1Hz, limit 10) — a lost HELLO must not silently downgrade the whole session to legacy behavior (0.10.0-rc.15: sharer never records viewer caps, RTT/NACK/FEC all dead, because the sharer answered from a KEEPALIVE-learned address with no caps recorded). `0x0A NACK` (generic-NACK FCI, ≤16 entries) triggers byte-identical retransmit from a bounded send-side ring, gated at 25%-of-bitrate token budget, falling back to PLI when evicted/over budget. `0x0B RECEIVER_REPORT` / `0x0C PING` (~1Hz) feed the congestion controller (loss → ±25%/+10% bitrate, then an fps ladder 60→30→15). **Stale/absent feedback must read as its own state, never as "clean"** — `feedbackIsStale` (per-viewer, only for `.receiverReport`-capable viewers) suppresses up-ramp/fps-recovery without driving a cut. Reorder buffer holds gaps by **time** (`reorderGapHoldNs` ~300ms), not packet count — a count-based window overflows in tens of ms at video bitrate, tearing every keyframe (`TS-GENERIC-001`). `0x0D FEC` is XOR parity per group of ≤N packets, interleaved (not batch-trailing) after that group's last media packet; adaptive per-viewer on RTT>150ms ∧ loss>2%, group size ladders 10/7/5, gates off after two clean windows. RR's 24-byte form adds `fecRecovered`/`nackRecovered` — **both** feed raw-loss (not just residual), or NACK's own success reads as a clean link and starves FEC on high-RTT paths. `PROFILE_NO` (`0x09`) latches 8-bit HEVC; primary 10-bit gate is caps bit5 `.tenBit` — a sharer encodes once and fans out, so one incapable viewer force-downgrades the whole share (`tenBitDowngradeNeeded`, latched, never lifts mid-share).
- **Viewer admission.** Approval-required by default (`TAILSCREEN_OPEN_DOOR=1` bypasses). `ViewerAccessPolicyStore` keyed by Tailscale **StableNodeID** (never wire-claimed hostname) — deny outranks open-door. `HELLO_DENY` (`0x08`) + `SERVER_BYE` both for permanent block and for one-time kick (nothing remembered on kick). 30s expelled-addr quiet window answers straggler KEEPALIVEs with denial so a kicked client doesn't silently re-register.
- **Audio — UDP RTP, separate SSRC space.** Opus, mono, 48kHz, 20ms/frame. PT 98 voice, PT 99 system audio (sharer→viewers only; captured with `excludesCurrentProcessAudio` to avoid re-capturing viewer voices). SSRC 0 = sharer voice, 1 = reserved system audio, 2+ = viewers. Inbound gate only accepts PT 98 from viewers (also the anti-spoof for PT 99). `VoiceMixer` sums same-slot frames per SSRC before one shared playback queue — feeding a queue multiple times per slot without mixing garbles both.
- **Annotations/control — TCP framed** `[type:1][len:4 BE][payload:N]` JSON. Gated to **admitted viewers by peer IP** (not by connection identity claims); pending/denied/blocked/expelled peers' ops are dropped, never applied or fanned out. Viewer toolbar gated on HELLO_ACK's `.annotations` bit.
- **Remote control — TCP framed.** `.controlRequest`(0x06)/`.controlGranted`(0x07)/`.controlRevoked`(0x08)/`.inputEvent`(0x09)/`.controlReleased`(0x0A). (0x0A-0x0C collide in name only with UDP NACK/RR/PING — disjoint spaces.) Keys are USB HID usage IDs + a 5-bit neutral `KeyModifiers`, never raw `CGKeyCode`/`CGEventFlags` on the wire. Single grantee; granting a new one revokes the old. `RemoteControlPolicy.shouldInject` admits only the grantee's `connectionID` — unspoofable, un-inheritable across NAT rebind. Auto-revokes on disconnect/Stop Sharing/`.controlReleased`/panic hotkey (⌃⌥.). Injector is TOCTOU-safe (atomic `active` gate) and synthesizes button-up on revoke mid-drag. Injection runs in the **main process** via `CGEvent` (needs Accessibility TCC, not Screen Recording). Keyboard is whole-Mac (not scoped to shared window) — deliberate, disclosed to the sharer at grant time.
- **Open link on sharer — TCP `.openLink` (`0x0E`), viewer→sharer, UI-gated on sharer caps bit 6 `.openLink`** (advertised iff the host passed `promptsForLinks: true`). URL shape rules are byte-level (`OpenLinkPayload.isAcceptable`, mirrored in Go's `IsAcceptableLink`) so both implementations agree without a URL parser; a bad URL is dropped, never repaired. Admitted-viewer gate like annotations; `LinkOfferQueue` bounds offers (one per connection, 4 total, die with the connection). **Never open without a click, never add auto-open** (TS-LNK-010: auto-open lets any viewer put any page on the shared screen). The OS notice (`.linkOffered`) has no buttons on purpose: a banner may truncate the URL.
- **Metadata — TCP request/response, same connection** (no dial-back, so the answer provably reaches the actual requester). Request-to-share `0x04` → `shareResponse` `0x05`. Metadata query `0x0B`/`0x0C` (name collides with UDP RR/PING — disjoint spaces). Pending-request dedup keys on **source IP**, never wire-claimed hostname.
- **Stream carriage (reliable-transport profile, spec §2.2).** Whole datagram plane (HELLO, RTP, RR, PING) as `.mediaDatagram` (TCP `0x0D`) frames for viewers without usable UDP. No caps bit — electing is sending HELLO as a frame; that connection becomes the media route. `.nack`/`.fec` masked off (`streamHelloCaps`) since retransmit/parity are dead weight on lossless TCP. Behaves as legacy PLI-only viewer for backpressure/congestion.
- **Guest (share-by-token) transport.** Per-link ephemeral WireGuard tunnel from an opaque `tc…` token (fork's `guest` package). **Nothing on the wire inside the tunnel differs** — second UDP/TCP listeners beside the tailnet ones, same handlers. Guests are a second **admission class**: identity = WireGuard node key, approval mandatory every join (remembered-allow/open-door/ask-to-share pre-approval don't apply), Deny also evicts the key at the tunnel. `SharerLinkSession` owns link lifecycle for all three hosts. Shapes pinned in `ShareLinkFormat`/`ShareLinkFormatTests`.

## Pitfalls

- **Route new listeners/dials through `NetworkConfig.tailscreenPort`** — never a bare `7447` literal.
- **Annotation ops must fan out in strict order, synchronously.** `.undo(X)`/`.clearAll` only make sense relative to ops already delivered; separately-spawned `Task`s reach a shared await point in unpredictable order and strand strokes permanently. `TailscaleScreenShareServer.enqueueAnnotationBroadcast` is synchronous, one consumer drains the outbox in order — never re-wrap it in a `Task`. Same rule at each host's outbound queue (mac `OrderedOutbox`, GTK `AnnotationForwarder`/`InputForwarder`, WinUI `Outbound`). Pinned by `AnnotationFanOutOrderTests`.
- **IPv6 admitted-viewer checks silently fail over the guest tunnel or an IPv4-less tailnet.** `isAdmittedViewerIP` compares `ipFromAddr` reductions with `==`. TCP addresses (`tailscale_getremoteaddr`) keep IPv6 brackets; splitting on the last colon (which is inside a portless bracketed IPv6 literal) mis-parses it. Match the bracket form before looking for a port. `PeerAddressParsingTests`' two `reduceToTheSame` cases are the contract.
- **"Ask to Share" reading as "No reply" means nothing is listening** — a share-less host has no `TailscreenControlListener` unless it owns one independent of the share lifecycle. Use `SharerAskToShareCoordinator` (pinned by `SharerAskToShareCoordinatorTests`); answer on the connection the request arrived on (never dial back); fire `onPreApproveViewer` before `onStartShare` so the invited peer skips the approval gate.
- **"Deny & Block" appearing to do nothing is the StableNodeID resolution queue, not a bug.** ID arrives a beat after the connection via LocalAPI lookup; `SharerAccessCoordinator` queues and applies on the next roster tick. Feed **both** rosters (connected + pending) to `noteRoster` together, and prune queued intent when a pending viewer resolves — or a disconnect-then-reconnect from behind the same NAT (different machine) inherits the stale block. macOS must coalesce roster notes to end-of-turn (`scheduleNoteRoster`) since `onPendingViewersChanged`/`onViewersChanged` fire on separate turns.
