# Browser viewer (`web/viewer`)

A static page that watches a share from a browser tab: the fork's `guest` client and `sdk/go` compiled to js/wasm, WebCodecs for decode, a canvas to draw on, Web Audio for sound. It only *views*, only as a **guest** (the web form of a share link, token in the URL fragment), and — because a browser has no UDP — only over the **stream profile** (spec §2.2, `.claude/rules/protocol.md`'s stream-carriage bullet): the page sends its HELLO as a `mediaDatagram` frame and the whole datagram plane rides the TCP channel from then on. The design and its history are `plans/browser-viewer.md`; the module's own README is the file map. This file is what breaks when you touch it.

## Three layers, and which one owns what

- **`main_js.go` / `session_js.go` — the wasm.** Dial (`tailscreenGuestDial`), §10 framing, HELLO/control builders, the datagram classifier, `tailscreenNewSession()` (reorder → depacketize → access units, plus the KEEPALIVE / receiver-report / PLI cadences driven by the page's clock through `tick`), `tailscreenDecodeMetadata`, and `tailscreenConstants`. **Every wire byte comes from `sdk/go`** — the same code the conformance vectors pin. Never re-implement a format in JS, and never hard-code a type byte, payload type or interval in the page: read it off `tailscreenConstants`, and add a key there when the page needs a new one. The exported surface is documented in the header comment of `main_js.go`; keep that comment true.
- **`wire.js` — the pure wire half of the page.** The W3C `KeyboardEvent.code` → USB HID usage table (TS-RMT-022), the modifier bit field (TS-RMT-023), the §12.2 input-event and §11 annotation JSON builders, the `AnnotationStore`, and `tokenFromInput` — the join field's parser, which mirrors `ShareLinkFormat.token(fromUserInput:)` rule for rule (bare `tc…` token, `tailscreen:` link, web link from any host, fragment before `token` query item): **change both or neither**, and keep `wire.test.mjs` and `ShareLinkFormatTests` on the same cases. No DOM, no wasm, so `e2e/wire.test.mjs` checks it in plain Node against the spec's own examples. A new key, modifier or JSON field lands here with a check there.
- **`viewer.js` — the page.** The loader, the loop, `VideoPath` (WebCodecs → canvas), `AudioPath` (Opus → `AudioContext`), the placards and HUD, the join field (`showJoin`, shown when the URL carries no token; a submitted token goes into the fragment via `replaceState` so Reconnect and a bookmark keep working, and a token that never dialled comes back to the field with the reason), the control/draw modes on the `#ink` overlay, and `applyCaps`. Its `window.__viewer` object is **the e2e's contract** — `state`, `rtpVideo`, `decodedFrames`, `serverCaps`, `controlling`, … — so renaming or dropping a field there is an e2e change, not a refactor.

## Rules

- **Strings go through the catalog, by hand.** The page renders `dist/strings.json`, exported by `tools/export_strings.py` from the keys listed in `tools/strings.txt` — each one must ALSO exist in TailscreenL10n's catalog (it fails the export otherwise). `make test-l10n` scans the four Swift source trees, **not** this page, so a new user-facing string here is two edits: `strings.txt` and the catalog (`Packages/TailscreenL10n`, every language). A key missing at runtime renders as the English key, silently.
- **Capability-gated UI is hidden, not disabled.** Request control appears only when the sharer's HELLO_ACK carries `remoteControl`; the drawing tools only with `annotations` — the same gates as the apps, and what the e2e asserts: a headless sharer renders nothing, so it advertises no `annotations`, and it advertises `remoteControl` only when run with `--allow-control`. Never show a button that would send a frame the sharer drops.
- **The stream profile is not optional here.** There is no UDP fallback to keep working; NACK/FEC are never advertised (TS-STM-005). Loss shows up as delay, and the sharer sheds frames for a backed-up stream viewer — a stall is a keyframe request away (`session.requestKeyframe()` → PLI), never a reason to add recovery logic to the page.
- **A stroke's `width` is in points against a 1000-px short edge** (TS-ANN-005; `Annotation.defaultWidth` = 3, `AnnotationRasterizer.referenceShortEdge` = 1000), never a fraction of the frame. The page once sent `0.004` — right on its own canvas, a 0.004-point hairline on every sharer, and an app's `3.0` would have painted 2000 px wide here. `wire.js` owns the unit (`annotation.defaultWidth`, `annotation.strokePixels`) and `wire.test.mjs` pins the page's `add` against the conformance vector's example byte for byte; the e2e cannot see this (a headless sharer renders nothing), so that test is the only gate.
- **Audio has its own check, because the spike cannot reach it.** The headless Linux sharer sends no audio, so `e2e/audio.test.mjs` feeds real Opus packets (`e2e/gen_opus.py`, libopus through ctypes — the apps' encoder shape: 48 kHz mono, 960 samples per packet) straight into `AudioPath` in a real browser and asserts decode, scheduling, audible samples, the per-type counters (`audioVoice`/`audioSystem` — PT 98 at SSRC 0 must decode exactly like PT 99), no play errors, and on Chromium a running `AudioContext` (the autoplay flag stands in for the click; headless Firefox stays suspended by design, so it is asserted on everything else). It runs inside `make test-web-spike` before the spike. The failure that looks like nothing is a **suspended context**: packets tick, the decoder runs, no sound — so the page logs and shows the state (`ctx` in the HUD), and resumes it on any later pointer or key.
- **WebCodecs needs a secure context** (`https://` or `file://`). `VideoDecoder` is simply undefined over plain `http://` from a non-localhost host, which reads as a broken page rather than a policy — the placard says so; keep it saying so.
- **H.264 goes in as `avc` with an avcC** built from the in-band SPS/PPS (`avcC()`); HEVC as Annex B with a `hev1.…` string. When `isConfigSupported` says no, the page calls `session.codecUnsupported()` (CODEC_NO, spec §4) and the sharer re-encodes as H.264 — the browser-side half of a protocol exchange, so do not "fix" an unsupported codec by transcoding in JS.
- **The wasm is fetched gzipped and inflated in the page** (`wasmResponse()` → `DecompressionStream`), because GitHub Pages does not compress `application/wasm`: 34 MB raw vs 7.8 MB. The single-file bundle (`tools/bundle.py`) inlines the same gzip as base64 under `window.__tailscreenInlineWasmGzB64` and the same loader recognises it. The raw `viewer.wasm` is the fallback only where `DecompressionStream` is missing. A new file the page loads must also be added to the `publish()` list in `.github/workflows/pages.yml` and to `bundle.py`, or it works locally and 404s on the site.
- **Hosting has a channel rule.** `/next/view/` tracks `main`; the root `/view/` (where `ShareLinkFormat.webViewerURL` points) is published only when the latest *stable* release tag carries `web/viewer/index.html` — see `.claude/rules/ci.md` → Pages. A page-only change is live on `/next` minutes after merge and on the root at the next release.
- **`go.mod` `replace`s** the fork onto the submodule checkout and the SDK onto `../../sdk/go`, so the wasm build, the c-archive build and the apps pin the same commits. Bumping the submodule pointer changes what the page dials with; `go.sum` follows.

## The e2e, and its traps

`make test-web-spike` (Linux; CI's `linux-web-spike`) runs `e2e/wire.test.mjs`, builds `cmd/localderp` (a DERP+STUN+`/derpmap` stand-in with a self-signed cert and `InsecureForTests` in the token's region) and `tailscreen-sharer-linux`, then drives `e2e/spike.mjs`: Xvfb with a gradient → the sharer in link-only mode (`--link --link-relay-map-url … --approve-guests --allow-control --grant-control`) → the page in a real browser, asserting `acked`, ≥ 50 video datagrams, ≥ 10 decoded frames with a non-flat canvas, a pointer move landing on the Xvfb (read back by `xdotool`), and the drawing tools hidden. Knobs and the sharer flags are in `.claude/rules/testing.md`. What has actually bitten:

- **Playwright's own Chromium has no H.264.** Every H.264 config reports unsupported, so the decode assertions downgrade to transport-only with a NOTE. The harness prefers Google Chrome (`playwright install --with-deps chrome`; `PW_CHANNEL` overrides) and CI installs it; `PW_BROWSER=firefox` runs the same assertions on Playwright's Firefox, which decodes H.264. Safari is unrun.
- **The sharer's `GuestServerNode` must be retained** for the life of the share (the Linux sharer keeps it in a global). Letting it go after `token()` closes the DERP connection and the browser's bootstrap is simply never answered — a hang with nothing in either log.
- **A container's `HTTPS_PROXY` captures the loopback `wss://`.** The harness strips the proxy variables from the browser's environment and launches with `--no-proxy-server`; a page that dials the relay through the agent proxy fails TLS against localderp's cert and looks like a relay outage.
- **`deepStrictEqual` across realms fails** on objects that crossed from the page: compare through `JSON.parse(JSON.stringify(v))`.
- **`NODE_PATH="$(npm root -g)"`** is how the harness finds the global `playwright` module; the Makefile sets it, a bare `node e2e/spike.mjs` does not.
- **`--approve-guests` and `--grant-control` are automation-only**, the guest-side twins of `TAILSCREEN_OPEN_DOOR` — never for a share with a person in front of it.
