# CI/CD

**CI uses submodules.** New workflows that build must pass `submodules: recursive`.

## Shared build definitions

The per-OS app build is defined once and called from both its per-push and release workflow: `app-macos.yml` (release.yml + `build:notarized` PR build), `app-windows.yml` (build-windows.yml + release.yml), `app-linux.yml` (build.yml's `linux-app-arm64` + release.yml's arm64 packaging). `.github/actions/bootstrap` is the composite action every build job runs after checkout: applies the TailscaleKit patch series, materializes symlinks Windows checkouts mangle, sets up Go from the submodule's `go.mod`, produces/restores `libtailscale.a` for the target (`host`, `macos-universal`, `windows-amd64`/`windows-arm64`). It does NOT own the checkout or `git config core.symlinks` (must precede checkout).

Rules:

- **`.build` caches are saved only from `main`, restored everywhere.** A branch-scoped cache save still spends the repo's shared 10 GB budget without anyone being able to restore it — saving from every branch starves `main`'s caches via LRU eviction (zero hits repo-wide, full ~23 min Windows dependency rebuild every run). Branch runs restore via `restore-keys` prefix and skip saving. Two corollaries: the save key must hash the same bytes the restore key hashes (Linux/Windows jobs discard SwiftPM's mid-job lockfile rewrite before hashing), and save/restore `path:` lists (incl. `!`-exclusions) must be IDENTICAL — the path list is hashed into the cache entry's version, so a mismatch is invisible ("Cache not found" on restore vs. "Unable to reserve cache" on save) while looking healthy.
- **Caches are keyed on the matrix/arch dimension** (`runner.arch` in `libtailscale.a`, `Apps/windows/.build`, `Apps/linux/.build` keys) — an x64 tree restored into an arm64 build has shipped as a bug once.
- **`use_cache`/`cache` is policy, not convenience.** CI passes true; every release workflow passes false, so shipped artifacts always compile from source.
- **`build-windows.yml`'s `paths:` list must contain every input to its jobs**, including `app-windows.yml` and `.github/actions/bootstrap/**`. Holed twice; symptom both times was a green branch behind a real failing Windows result.

## Pitfalls

- **`lint` fails naming no file.** Reporter `github-actions-logging` puts the path in annotation metadata, which the log API strips. Reproduce on macOS with `make lint-tools && make lint` (installs the same `portable_swiftlint.zip` CI uses). On Linux, build SwiftLint from source at `make -s print-swiftlint-version` and run `LD_LIBRARY_PATH=/opt/swift/usr/lib swiftlint lint --baseline .swiftlint-baseline.json --strict --quiet` (the `LD_LIBRARY_PATH` is required — without it: `Loading libsourcekitdInProc.so failed`). Check if it also reproduces on `origin/main` in a worktree before assuming you introduced it.
- **A local `make lint` disagreeing with CI is the version, until proven otherwise** — `SWIFTLINT_VERSION` in the Makefile is asserted by the `lint` target. Underlying cause: the baseline records each frozen violation's `reason` *string*, so a linter release that rewords a message un-freezes it (e.g. `redundant_nil_coalescing` between 0.63/0.65). Fix: `make lint-tools`; `TAILSCREEN_SWIFTLINT_ANY=1` overrides, only in the commit bumping the pin.
- **Adding a package dependency to `Apps/linux` breaks a leg you didn't touch.** System libraries are listed in three places that must move together: the `linux-app` job in `build.yml`, `app-linux.yml` (also `linux-app-arm64` + release packaging), and `Apps/linux/packaging/README.md`. Miss the first two → the new dep's C shim fails its own `#include` in CI only (a dev machine already has the headers). Miss the third → the tarball ships a binary whose `DT_NEEDED` names a library the user lacks. Also check whether it's a runtime dependency: the AppImage picks those up via linuxdeploy's `DT_NEEDED` scan, the tarball does not.
- **A new macOS workflow dies in `emit-module` with "'opus.h' file not found".** Needs both `brew install opus` AND `/opt/homebrew/lib/pkgconfig` on `PKG_CONFIG_PATH` — SwiftPM on Apple-silicon runners doesn't search Homebrew's pkgconfig dir. Set as job-level `env` alongside the TailscaleKit dir; an `export PKG_CONFIG_PATH=...` inside a run step SHADOWS rather than appends to the brew path. Note `app-macos.yml` itself builds a static universal libopus from source instead (so the shipped `.app` carries no Homebrew dylib) — copy whichever matches the job's purpose.
- **Windows render self-test (`winvideo-selftest`)** renders `makeColorBarsFrame()` through `CWinVideo`'s D3D11 shader to an offscreen target — no GPU or desktop needed (HARDWARE→WARP fallback). Exit code **3** = wrong pixels (see `WINVIDEO_SELFTEST bar*` lines); **2** = no D3D11 device at all, a runner-image regression. It **must run out of the staged `dist/`**, not a bare `.build` exe — needs the Swift runtime DLLs and `opus.dll` (vcpkg builds shared) staged beside it. Exit **127** from a Windows exe under git bash means the PE failed to *start* (commonly `STATUS_DLL_NOT_FOUND`), not "file not found". An **empty** self-test log means the process never ran (`winvideo_init` always prints and flushes) — not "no output". `$SDKROOT`-style native Windows paths can't be walked by MSYS `find` (matches nothing, says nothing).
- **The arm64 tsnet probe exits `0xC0000135` with empty output, intermittently**, on `windows-11-arm` — a loader-level runner transient, recovered by an untouched rerun. The "Check tsnet node creation returns" step retries once on that exact code (a genuinely missing DLL fails both attempts).
- **A Linux leg is cancelled at exactly `timeout-minutes` inside `apt-get install`, everything after `skipped`.** Not the leg failing — the container's apt is hitting the global `archive.ubuntu.com` mirror instead of the runner's Azure-local one. `.github/actions/apt-mirror` (called right after checkout, before the first `apt-get`) rewrites sources to `azure.archive.ubuntu.com`, proves it with its own `apt-get update`, and reverts if that fails; also sets `Acquire::Retries`/`Timeout`. Any new container job needs this step too.
- **A leg fails to LINK a symbol nothing in it calls.** A `swift test` target is an executable and links the whole dependency graph — anything reaching `TailscreenSharer` reaches `TailscaleKit` and needs `libtailscale.a`, whether or not the test calls tsnet (`swift build` of the same package passes fine, since a library target is never linked). Fix: set `libtailscale: host` + `go: preinstalled` on any leg running `swift test` over a package depending on `TailscreenSharer`. **Not reproducible locally on a machine that has ever run `make tailscale`** — the archive sits in `Packages/TailscaleKit/lib/` and gets picked up regardless. To actually reproduce: move `libtailscale.a` aside, `rm -rf` the package's `.build`, retest, then restore it.

## Workflows

Ten files under `.github/workflows/`; find current jobs/legs with `rg` rather than trusting a list here.

### Naming

- File name = role, hyphenated, variant last (`build.yml`, `build-docs-only.yml`, `build-windows.yml`); the three reusable per-OS builds are `app-<platform>.yml`. Never `<platform>-<role>.yml`.
- Workflow `name:` is Title Case, variant parenthesised (`Build`, `Build (Windows)`, `App (Linux)`, …) — also the concurrency-group key for build*.yml.
- Job ids are lowercase-kebab and ARE the check name; don't add a `name:` that just repeats the id. A job that `uses:` a reusable workflow reports as `<job id> / build`, so ids carry the platform themselves (`linux-app-arm64`, `windows-app`).
- Step `name:` is Sentence case, imperative ("Build the app"), never a bare noun or package name.

**`build` is the one required status check on `main`** — its job id is frozen in `build.yml` and `build-docs-only.yml`. `scripts/test-release-wiring.py` pins `release.yml`'s job ids `macos`/`linux`/`windows`. The `linux-packages` matrix leg names are quoted throughout PR history — rename only deliberately.

### Build

`build.yml` runs `make build` + `make test` on every PR/push to `main` (skips doc-only changes, `concurrency.cancel-in-progress`). Also here:

- **`linux-web-spike`**: bootstrap, then its own `actions/setup-go` (needed for wasm build + localderp even on a libtailscale cache hit), apt Node + Playwright + Google Chrome (`playwright install --with-deps chrome` — Playwright's own Chromium ships no H.264 decoder), then `make test-web-spike`. See `.claude/rules/testing.md`.
- **`linux-packages` matrix** — one job per leg (`fail-fast: false`), all on a `swift:6.3-noble` container: `linux-protocol` (`swift test --package-path Packages/TailscreenKit`; needs `go: preinstalled`+`libtailscale: host` since `TailscreenSharerTests` links `TailscaleKit`), `linux-tailscalekit` (builds libtailscale + runs TailscaleKit's Linux tests), `linux-tsan` (`--sanitize=thread` over the same package — **not** `continue-on-error` unlike macOS's `test-tsan`, because this package imports no Apple framework, so a hit here is a real race — reproduces by reintroducing `VoiceDownlink.reset`'s missing lock), `linux-differential` (`make libtailscreen` + `swift test --package-path Packages/TailscreenDifferential`, `PKG_CONFIG_PATH=$PWD/sdk/go` — own package because two Go c-archives can't share one binary's cgo export symbols; reproduce with `make test-differential`), `linux-l10n` (`swift test --package-path Packages/TailscreenL10n` plain + `--sanitize=thread`; scans all four source trees for `L("…")` keys, the only check on GTK/WinUI strings), `linux-opus` (OpusKit round-trip), `linux-ffmpeg` (FFmpegKit H.264 + AVCC↔Annex-B), `linux-x11-capture` (X11CaptureKit + `xvfb-run` live capture), `linux-alsa` (ALSAKit vs. ALSA `null` device), `linux-portal` (PortalCaptureKit — unit tests, `portal-probe --link-check`/`--handshake-test` against a fake portal on `dbus-run-session`, then real PipeWire daemon tests `--pipewire-capture-test`/`--pipewire-format-guard`/`--pipewire-malformed-guard`; `dbus-run-session` is load-bearing — without it those SKIP with exit 0 rather than failing), `linux-notify` (GNotifyKit against real `dunst` on `dbus-run-session`+Xvfb via `gnotify-probe --live-check`; also runs WinNotifyKit's non-Windows-buildable half since its shim stubs off Windows), `linux-hotkey` (X11HotkeyKit real `XGrabKey` via `x11-hotkey-probe --live-check`, incl. a Num Lock repeat and a second-connection refusal check; also WinHotkeyKit's non-Windows decisions), `linux-wasapi` (WASAPIKit non-Windows-buildable logic only — no apt install needed), `linux-xtest` (XTestInjectKit: unit tests, `xtest-probe --audit-keysyms`, `--live-check` real injection+readback). Plus `linux-viewer` (`xvfb-run swift test --package-path Packages/TailscreenLinuxBackends` — `PipelineIntegrationTests` + `CaptureEncoderTests`; also `TailscreenVideoFFmpeg`) and `linux-app` (builds the GTK app; headless GL render self-test, `--overlay-self-test`, `--overlay-input-self-test`, `--capture-backend-report` under Xvfb) and `linux-app-arm64` (`app-linux.yml`, `ubuntu-24.04-arm`; builds arm64 libtailscale + GTK app in release config, hard gate, uploads `tailscreen-linux-arm64.tar.gz`).
- **`build-release`**: `swift build -c release` compile check, required.
- **`make sil-isolation-report`** is diagnostic only, never a gate: reports every function calling `swift_task_isCurrentExecutor` (the SE-0423 precondition). On the macOS app it's **524 functions** — 370 SwiftUI view-body closures, 5 AppKit, ~150 stdlib higher-order-function closures (`filter`/`map`/`sort`) from `@MainActor` code, all benign, vs. 2 real bugs — too noisy and too churny (`closure #N` renumbers on unrelated edits) to gate on. Use it by running before/after a change that adds a framework callback and diffing.
- **`callback-isolation` job** (`make lint-isolation`): rejects a closure *literal* passed to a framework callback in `API_CALLBACKS` from actor-isolated code — that closure inherits isolation, SE-0423 plants a dynamic executor precondition, and the framework then calls it off-actor → `EXC_BREAKPOINT`. Both the broken and fixed forms compile clean under `-strict-concurrency=complete`; no frontend flag catches this. Three instances have shipped and crashed before this existed. Not a SwiftLint rule (needs enclosing-type/function isolation, not regex-visible). Runs on Ubuntu, no toolchain needed. `API_CALLBACKS` is a maintained allowlist — fails open if incomplete.
- **`release-version` job**: `scripts/test-release-version.sh` over `scripts/release-version.sh` (tag → version/MSIX identity derivation) plus `scripts/test-release-wiring.py` over `release.yml`'s job graph (no release job may `needs:` a PR-only job — GitHub silently propagates SKIPPED through `needs`; shipped a `.app`-less release once) and every `gh release upload` either runs in a checked-out job or passes `--repo`.
- **diff-coverage gate**: `scripts/diff-coverage.sh`, lcov `DA:` vs. `git diff -U0 origin/main...HEAD`, fails under 70% changed-line coverage; `continue-on-error: true` (flip-to-required TODO).

### Screenshots

`workflow_dispatch` + `pull_request` scoped to its own file. Fans out to the three `app-*.yml` with `screenshots: true`; all apps launch with `--ui-preview` (seeded deterministic hub, no tsnet). Per-state flags spelled identically across platforms: `--ui-preview-video`, `--ui-preview-sharing`, plus platform-specific ones (`--ui-preview-placard` Linux, `--ui-preview-request` macOS) and `--ui-preview-welcome` (pre-sign-in state, seeds no profile). Capture: Xvfb+ImageMagick (Linux), `CopyFromScreen` (Windows), `screencapture` (macOS — hosted runner has the Screen Recording grant). Every capture step checks the app process is alive first.

**macOS leg is what the docs site publishes** (`docs/assets/screenshots/`). Crops with `screencapture -l <window>` (window id passed as `--ui-preview-window-file` **argument**, since launch is via `open`, which forwards `--args` but not env). Asks for HiDPI first (best-effort — falls back to 1x rather than failing). **A wallpaper-only PNG in the artifact means the Screen Recording grant is missing** — extend the `--ui-preview` modes rather than reach for pixel assertions. The annotation seed omits `.click` on purpose (ephemeral, swept by a real timer before capture).

### Soak

`soak.yml`, nightly (`cron: 17 3 * * *`) + `workflow_dispatch`: runs `SoakTests` with `TAILSCREEN_SOAK=1`. Deterministic — a red nightly names its reproducing seed.

### Pages

`pages.yml` deploys the docs site: root from the latest **stable** release tag, `/next/` from `main`. Also builds the browser viewer (submodules, Go from the fork's `go.mod`, `make web-viewer`), publishing under `_site/next/view` always and `_site/view` only when the resolved stable tag ships `web/viewer/index.html` (same channel rule as docs — one wasm build from `main` serves both, since unknown wire frames are skipped on both sides). `paths` filter includes `web/viewer/**` and `sdk/go/**`. Published set is exactly what the workflow's `publish()` copies (`index.html`, `viewer.js`, `wire.js`, `dist/{viewer.wasm,viewer.wasm.gz,wasm_exec.js,strings.json}`) — a new file the page loads must be added there.

### Release

Fires when a GitHub release is **published**, plus an on-demand PR label and `workflow_dispatch` against a tag. `version` job derives tag/version/MSIX identity once, fans out to: **macos** (shared `app-macos.yml`, also the `build:notarized` PR build — codesigns + notarizes only when all `APPLE_*` secrets are set, else uploads unsigned with a warning; a "Stamp the build" step rewrites `BuildInfo.commit` and fails the job if the `sed` doesn't take), **linux** (x64/arm64 matrix via `app-linux.yml`, AppImage + tarball per arch) + **linux-upload** (separate non-container job — `gh` isn't in the swift container), **windows** (both arches via `app-windows.yml`, zip + self-signed MSIX + the signing cert's `.cer` per arch; SignPath replaces signing before winget submission). PR labels: `build-linux-package`, `build-windows-package`, `build:notarized`; a shared `unlabel` job removes whichever fired so re-adding rebuilds. **No `concurrency:` block** on purpose — `pull_request: [labeled]` fires once per label, and grouping would let one label's run cancel the other's.
